# dotfiles

Personal Linux dotfiles for Arch-based systems running [niri](https://github.com/YaLTeR/niri) + [Noctalia](https://github.com/noctalia-dev/noctalia-shell).

## What's in here

| Package | Stowed to | Notes |
|---------|-----------|-------|
| `fish` | `~/.config/fish` | Default shell config, aliases, functions |
| `zshrc` | `~/.zshrc` | zsh config (alternative shell) |
| `starship` | `~/.config/` | `starship.toml` + `update-noctalia-starship.py` |
| `fastfetch` | `~/.config/fastfetch` | |
| `ghostty` | `~/.config/ghostty` | Terminal emulator config |
| `nvim` | `~/.config/nvim` | Neovim config |
| `niri` | `~/.config/niri` | Wayland compositor config |
| `noctalia` | `~/.config/noctalia` | Shell/bar config |
| `fuzzel` | `~/.config/fuzzel` | App launcher |
| `hyprland` | `~/.config/hypr` | |
| `gtk` | `~/.config/gtk-3.0`, `~/.config/gtk-4.0` | |
| `wezterm` | `~/.wezterm.lua` | |
| `wallpapers` | `~/.local/share/wallpapers` | |
| `plasma` | `~/.config/` (merged) | `kdeglobals`, `powerdevilrc` |
| `systemd` | `~/.config/systemd/user` | User-unit overrides, including portal auto-restart |

## Machine profiles

Three profiles are supported: `home`, `work`, `laptop`.

The profile is saved to `~/.config/dotfiles/machine.env` on each machine and is **not synced to git**. It controls:

- Niri layout column widths and default window width
- Monitor output config (`machine.kdl`)
- Machine-specific window rules (e.g. work Chrome PWA apps)
- Which extra packages get installed by `2-install-pkgs.sh`

### Files that are machine-local (gitignored)

| File | Why |
|------|-----|
| `~/.config/dotfiles/machine.env` | Machine identity |
| `~/.config/niri/machine.kdl` | Generated from `machine.kdl.<profile>` |
| `~/.config/niri/output.kdl` | Monitor names differ per machine |
| `noctalia/.config/noctalia/colors.json` | Runtime state, regenerated by Noctalia on theme change |

## Fresh install

### Step 1 — Clone the repo

```bash
git clone https://github.com/yourusername/dotfiles ~/dotfiles
cd ~/dotfiles
```

### Step 2 — Shell, terminal tools, and dotfiles symlinks

Installs: `fish`, `zsh`, `starship`, `fzf`, `eza`, `zoxide`, `stow`, `fastfetch`, `ghostty`, `micro`, `bat`, `fd`, `neovim`, `yay` (if missing).

Stows: `zshrc`, `fish`, `starship` (includes `update-noctalia-starship.py`), `fastfetch`, `ghostty`, `nvim`.

Sets your default shell (fish recommended).

```bash
bash 1-install-shell.sh
```

### Step 3 — GUI and system packages

Shows an interactive multi-select list of package manifests, then installs the selected groups immediately. Machine profiles are reserved for dotfile customizations such as Niri KDL files.

```bash
bash 2-install-pkgs.sh
```

Use Tab to toggle manifests and Enter to install. Escape cancels without making changes. To add packages, edit the newline manifests under `manifests/packages/`:

```bash
manifests/packages/interactive
manifests/packages/work-apps
manifests/packages/gaming
```

### Step 4 — Dotfiles, niri, noctalia, and machine profile

Stows all remaining config packages and generates the machine-specific niri config.

```bash
bash 3-install-dots.sh
```

On first run you'll be prompted to select a profile:

```
Select machine profile:
  1) home    (default)
  2) work
  3) laptop
Selection [1/2/3]:
```

The choice is saved to `~/.config/dotfiles/machine.env`. On subsequent runs you'll be asked to confirm or change it.

This also copies `niri/machine.kdl.<profile>` → `~/.config/niri/machine.kdl` and, if niri is running, auto-detects your connected output via `niri msg outputs` and substitutes it for the `__NIRI_OUTPUT__` placeholder in the template. If niri isn't running (fresh install before first login), the placeholder is left in place — run `niri msg outputs` after logging in and edit `~/.config/niri/machine.kdl`. Niri includes this file for layout widths, monitor output, and machine-specific window rules.

Step 3 also installs user-systemd overrides and reloads the user manager. The `xdg-desktop-portal-gnome` override restarts that backend after a lost Wayland compositor connection, preventing Flameshot screenshot requests from hanging. The installer stops the current demand-activated backend after reloading; the next portal request starts it with the new policy. It also creates `~/Pictures/Screenshots`, which is required by the shared niri screenshot path.

### Omarchy-safe install (non-destructive)

If you are on Omarchy and want to keep its standard environment intact, use:

```bash
bash 4-install-omarchy.sh
```

What it does by default:

- Stages your shell, Hyprland, and app configs into `~/.config/dotfiles/omarchy`
- Adds source/include hooks for shell and Hyprland instead of replacing Omarchy base files
- Leaves app config directories untouched (staged only)

If you want to apply app configs too (with automatic backups), run:

```bash
bash 4-install-omarchy.sh --apply-apps
```

## Adding a new machine profile

1. Copy an existing template as a starting point:
   ```bash
   cp niri/.config/niri/machine.kdl.home niri/.config/niri/machine.kdl.newprofile
   ```
2. Edit it — update `output "__NIRI_OUTPUT__"` (auto-filled at install time), `preset-column-widths`, `default-column-width`, and any window rules.
3. Add `newprofile` as a valid option in `3-install-dots.sh`.
4. Run `3-install-dots.sh` on the machine and select the new profile.

Dotfile profiles do not select packages. Choose the desired package manifests interactively when running `2-install-pkgs.sh`.

## Existing machine — after pulling changes

If you've already installed and just pulled updates from git, you typically only need to re-stow changed packages. The safe way is just to re-run `3-install-dots.sh` — stow's `-R` flag (restow) handles it cleanly.

```bash
bash 3-install-dots.sh
```

Your saved machine profile will be detected and confirmed before anything changes.

## Niri machine config

Machine-specific niri settings live in `niri/.config/niri/machine.kdl.<profile>` in the repo.  
After install, `~/.config/niri/machine.kdl` is the live copy (gitignored).

The shared `config.kdl` includes it at the end:

```kdl
include "./machine.kdl"
```

To edit layout or output settings for your machine, edit the live `machine.kdl` directly, or edit the template in the repo and re-run `3-install-dots.sh`.

### Monitor output

`output.kdl` is gitignored. If it doesn't exist, niri will use default output settings. Create it manually:

```bash
# Check your output names
niri msg outputs

# Then create the file
nvim ~/.config/niri/output.kdl
```

## Noctalia notes

`colors.json` is gitignored — it's regenerated by Noctalia whenever you change colorscheme and should not be synced between machines.

`settings.json` is tracked. Changes to bar layout, widget config, and general settings should be committed. Color scheme changes are written to `colors.json` only, so they won't clobber `settings.json`.

The avatar image path in `settings.json` uses `~/dotfiles/Bulb.png` — adjust if you clone to a different location.

## Stale backup symlinks

If you see entries like `niri.backup.20260308102257 -> ...` in `~/.config/`, they're harmless leftovers from earlier installs and can be deleted:

```bash
rm ~/.config/niri.backup.* ~/.config/noctalia.backup.2026*
```
